# Browser user guide

1. Use the link supplied by the RE. Keep using the same browser profile and URL. Open online once to cache the application before offline use.
2. RE: initialize from an accepted baseline candidate, or restore the existing verified master backup. Do not create a second simultaneously active RE master. Starting an empty new project without importing a baseline is not implemented yet.
3. ARE/IOW: choose **Open field package**, select the encrypted `.gtdata` from the RE, enter its separately supplied passphrase and your name.
4. Enter the observation date, stage progress, activity, next action/issues and captioned/dated evidence. Check the proposed result, prepare submission and export the encrypted `.gtupdate` through the approved private channel.
5. RE: import updates, compare current/base/proposed values, resolve conflicts and accept, reject or request revision. Return each recipient's encrypted `.gtreceipt`.
6. Field users import receipts, then refresh with new `.gtdata`. Receipts update decisions; reference refresh updates approved values. Explicitly rebase older drafts before resubmitting.
7. RE: close the reporting period after checking approved records, dates and outstanding proposals. PDF and formatted Excel use the selected frozen report revision. Corrections create another revision.
8. Download full `.gtbackup` files regularly, keep passphrases separately, and use **Verify downloaded backup** on the saved file. Practise recovery in a separate browser profile. Ordinary PDF/Excel files are not full backups.

Data is local to the browser origin/profile/device. Clearing site data, private browsing, device loss or changing the hostname can affect access. Moving from a local preview to the hosted site requires a verified backup/team-package import; data does not move by itself. Keep the old master frozen during transfer.

Workspace shows capacity and update controls. Save work, retain an external backup and close other tracker tabs before applying a staged update. A waiting release can also activate when every old tab closes; the next version verifies/checkpoints saved data before loading it. Never clear site data as an update step.

Installation completion and instrument condition are separate: damage does not erase recorded installation. Installation reversal/applicability changes require an explicit reasoned RE edit. Numerical instrument readings and threshold alerts are not part of this release.

If saving fails, keep the tab open and export recovery data. Record the issue privately; do not paste sensitive records, files or screenshots into a public issue.
